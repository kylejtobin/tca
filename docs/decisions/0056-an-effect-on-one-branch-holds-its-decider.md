# 0056. An action performed on one branch of a choice holds a premise that decides the choice

Status: accepted

## Context

A charge must not run while the order is being screened, and a notification must go out only for a dear element. The run performs an action as soon as its premises are present, so an action whose premises are shared by both branches of a choice would be performed whichever branch held, and the reply made from the other branch would stand beside an effect it never asked for.

## Rejected

A scheduler that derives each effect's decision prerequisite from a compiled graph and gates it at run time: a plan the run obeys in place of the declarations, and a protection the developer cannot read on the page. Requiring every action to be reached from one branch only: a shared observation, asked on both branches, is one action. Taking reachability from one branch and not the other as the guard: a premise reachable from one branch only may still construct whichever branch holds, so the charge would run on a flagged order.

## Decision

For every union field whose members the proof has shown exclusive (0051), and every ordered pair of members `chosen` and `other`: an action that `chosen` leads to and `other` does not, through `Proof.reached`, must hold in the closure of its fields some decider of `chosen` against `other`, `deciders(present, against)`: a record whose hearer hears a record of `other`, a relation whose comparison contradicts one of `other`'s, or a selection whose counts exclude one of `other`'s. An action that holds none is refused as `undecided`: "Charge is performed when Outcome.which holds Priced and not when it holds Free, yet holds nothing that decides between them". The page then says what the business says, the charge is made from the order being clear, and the engine derives nothing at run time.

## Evidence

In the engine's test program, `Notify(Tell[Teller, Noted])` holds `high: High`; `Dear` holds `noted: Noted` and `Cheap` does not, so `Notify` is reached from `Dear` and not from `Cheap`; `High` contradicts `Low`, which `Cheap` holds, so `Notify` holds a decider and the proof passed. With the party saying 25 and one part, `Notify` was performed and `Dear.noted.word` was `dear`; with the party saying 2.50, `Notify` was never built. In the program with the faults, `Charge(Tell[Party, Charged])` holds only `element: Element`; `Priced` holds `charged: Charged` and `Free` does not; `Charge`'s closure holds neither `Low` nor any other decider, and `proven` raised `undecided` at `("Charge",)`. `Asked`, reached from both `Cheap` and `Dear` through the `Amount` that `Heard` carries, was not refused.

## Consequences

Unwritable: an effect that would be performed whichever branch of a choice held while being made from one of them. A shared observation is one action reached from both branches. Refuted by an action that must run on one branch and can hold no decider; none found, since the branch exists only by its deciders.
