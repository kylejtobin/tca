# 0052. A class no field names is refused at startup, as the mirror of a field no class fills

Status: accepted

## Context

A scalar nothing holds, a record a party may say that no conclusion holds, an action whose answer nothing uses, a connection no action is toward: each was constructed, performed or opened without a fault, and an effect could be performed for a reply that was never made from it.

## Rejected

A walk from each route through what brings each class, kept as a map: a second representation of what the fields already say. Exempting base classes by reading `__mro__`: a judgment about which classes count, not a read of fields.

## Decision

`used(cls)` is one read of the program's fields, the same read `missing` makes in the other direction: a class is used when some field of some declared class names it or a subclass of it, singly, as an element, or as what a computed field produces; a carrier is used when what it carries is used; an action is used when a record it hears is used; a route and the config are used by being. `proven` raises `unused` at `(class,)`, "no field holds X; hold it or delete it", for every other class the module declares. The engine keeps nothing: `named(program)` is the set of classes the fields name, read when asked.

## Evidence

The engine's test program `faults`, with `Stray(Scalar[str])` held by nothing: `proven` raised `unused` at `("Stray",)`. The test program `test_engine`, in which `Heard` is held by no field and carries `Amount`, which `Low` holds: `proven` passed, since the record is used through what it carries.

## Consequences

Unwritable: a fire-and-forget action, a party's answer nothing concludes from, a scalar declared and not held. A shared base class is used through its subclasses. Refuted by a class a program needs that no field can name; none found.
