| Stage | Machinery | Completion boundary |
|---|---|---|
| **1. World** | `base.py`, `relations.py`, `refusal.py` | Native scalar, record, and fact construction; computations derived from validated operands; comparisons and finite selections; supported immutable values; `tca_refuted` emitted only by world conditions after operand validation. |
| **2. Records and construction** | `record.py`, `construct.py` | Immutable invocation revisions; effect, attempt, and evidence identities; independent observations, provenance, admission, and conflicts; owned snapshots and type-sensitive equivalence. One complete Pydantic boundary returns `Witness`, `Refuted`, `Invalid`, or `Faulted`, retaining lineage and checking ownership of the actual returned value. |
| **3. Declarations and compiler** | `declare.py`, `graph.py` | **First settle the public declaration contract**, assessing provisional fixture constructs against required semantics and developer experience. Compile accepted inputs, references, products, conditionals, choices, work, receives, and collections. Resolve lexical bindings, preserve annotations, share by occurrence, and reject invalid declarations. |
| **4. Construction and demand** | `evaluate.py` | Construct complete holders, propagate consumer-specific demand, acquire decision prerequisites, resolve alternatives, preserve independent justification, and evaluate collection closure. Return explained proposals, waits, and withheld work. Introduce the single permission function with first-attempt permission; exercise evaluation against explicit evidence records. Verify memoization preserves behavior. |
| **5. Admission and historical permission** | `admit.py`; extend permission in `evaluate.py` | Establish provenance separately from admission. Use evaluated occurrences and constructed premises for receiving correlations and closure. Enforce source authority, correlations, cardinality, deduplication, and conflicts. Complete the same permission function in the order **conflict → admitted logical result → latest attempt’s established facts**. |
| **6. Local host** | `host.py` | Open invocations, evaluate revisions, commit intents, recheck justification, record attempts before dispatch, invoke adapters, and process immediate and delayed observations through the same admission path. Cancellation stops new work while preserving in-flight uncertainty. **The local execution engine now works end to end.** |
| **7. Durable host** | Persistence, restoration, inbox, worker coordination | Select infrastructure that satisfies the existing protocol; obtain explicit authorization for any architectural changes or documentation updates. Persist revisions and pinned artifacts, restore inputs faithfully, retain early deliveries, reject stale commits and duplicate dispatch authorization, and resume after process loss. Demonstrate recovery through crash injection. |

Each stage includes unit and integration tests under the testing standard, targeted defect detection for its safeguards, and composition with completed stages. Acceptance tests count as unlocked only when they pass through the real machinery their claims require.

Resolve the hard cases in the stage that owns them: sharing and scope in compilation; decision acquisition and independent demand in evaluation; contradictions and retries in permission; changed justification at dispatch; process loss in durability.
