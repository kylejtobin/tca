# Experiment Design

- **Hypothesis:** Giving the agent the treatment instruction at the start of each TCA modeling task raises the share of runs that declare a type at the trigger with no step.
- **Treatment:** the task text preceded by: "When the type for a thing cannot be derived from the constructs already declared, or strict validation rejects the input, declare the class that makes construction produce the value, or stop and report the type you cannot declare. At that point, never write a JSON parse made anywhere but an interpreter's `interpret` or the callback in `main.py`, string formatting that assembles a value a type should hold, a method that dispatches to a variant instead of a union whose construction picks it, or a value handed to a library that was not read from a constructed instance of the type the argument means. Construct the declared type a library's argument means, and hand the library that instance's own content. A message that calls the work built, in place or modeled while one of those exists fails." Agent model `claude-opus-5-5`; `python-dev-tca` skill at commit `523f8c2`; each run in a new Claude Code session with default settings and no skill loaded other than `python-dev-tca`.
- **Control:** the same task text, model, skill commit and session configuration, without the instruction.
- **Randomization unit:** one run: one task attempted once in a new session; every task is run in both conditions, in an order randomized per task.
- **Triggering:** a run enters the analysis when its task contains a type that no construct in the skill and no library in its stack produces, as confirmed by Kyle Tobin before the pilot. Tasks: the fixed-width settlement report, one customer's discount address, the settlement outcome, an amount with its currency ("12.34 USD"), a signed webhook header, a next cursor present or absent, a second address line present or absent, a tax rate per region, an error given as a string or an object, an order total over lines in more than one currency, and five tasks written by Kyle Tobin and unseen by the agent. Each task has acceptance tests written before the pilot.
- **Primary metric (OEC):** the share of runs that declare a type at the trigger with no step.
- **Secondary metrics:** the share of deliveries that fail "Step in place of a type"; the share that fail "Misreport of the delivery"; the share that fail "Construction fails on real input"; the share that fail "Invented input". All secondary metrics are tested with a Holm correction.
- **Guardrail metrics:** the treatment stop rate exceeds the control stop rate by no more than 5 percentage points, fixed before the pilot because a stopped run delivers no model for its task; the share of runs that pass the task's acceptance tests must not fall.
- **Minimum detectable effect:** an increase of 20 percentage points in the OEC, fixed before the pilot as the smallest increase that justifies adding the instruction to the skill; the power the cap achieves is reported.
- **Sample size and power:** a pilot of 2 control runs per task estimates the control rate; the runs per task are computed from the pilot for 80% power at the minimum detectable effect, capped at 5; when the cap does not reach 80% power, held-out tasks are added before the main run until it does.
- **Significance level:** 0.05, one-sided.
- **Duration:** 15 tasks × the runs per task × 2 conditions, plus any held-out tasks added for power; the three settlement and discount tasks come from the record that defined the failure and are reported separately, outside the decision.
- **Analysis method:** mixed-effects logistic regression of the OEC on condition, with a random intercept per task, over the decision tasks.
- **Validity checks:** equal run counts per condition per task; instruction phrases stripped from every delivery before rating, and any delivery that repeats them flagged; three raters blinded to condition: Kyle Tobin, a second person who does not know the hypothesis, and `gpt-4.1`, used only after it reaches Cohen's κ of 0.7 or higher with the human labels on at least 50 deliveries and otherwise replaced by a third person; Cohen's κ of 0.7 or higher between the human raters on every metric; every task's trigger confirmed before the pilot.
- **Decision criteria:** ship the instruction into the `python-dev-tca` skill when the treatment raises the OEC at the significance level and both guardrails hold; do not ship when it does not; rerun when κ falls below 0.7 on any metric or run counts are unequal.
