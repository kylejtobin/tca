# type-construction-engine

Reads a program's classes, proves them at startup, and answers a route by construction. The proof refuses, before anything runs, a field no class fills, a class no field holds, a record two actions hear, a class two computed fields produce, a scalar two carriers hold, a party the config holds twice, a cycle, a route or a collection in the wrong scope, a relation that declares no constraints or that its operands' bounds make certain or impossible, and a union whose members could both hold, decided from the relations' constraints and the scalars' bounds. An answer is a run: each pass asks Pydantic for every class not yet built from the instances its fields name, in the run the class belongs to, performs the actions that constructed together in one task group, and stops when the route itself constructs; a pass that builds nothing names each relation that did not hold and each field no class fills. The engine keeps nothing about a program: every question is a read of its fields. One span per answer, one per performed action. The engine defines no class of its own.

`tests/type_construction_engine/` holds the program the tests are, and the scenarios in `tests/features/`.
