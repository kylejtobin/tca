# type-construction-engine

Reads a program's classes, proves them at startup, and answers a route by construction. The proof places every class: the request, the connections and the constants once per run; an element once per element of the request or record that declares it; a record where its hearer is; a scalar where its carrier is; every other class where its premises are. It is a Pydantic model whose validator refuses the program with every fault at once, in the developer's names: a field no class fills, a cycle, a class with two sources, a class whose fields name sibling elements, a collection not one level down, a route that would exist once per element, a class no reply leads to, a bare primitive, a request that holds what does not arrive, no one deployment, two union members not proven exclusive, a relation its operands' intervals make certain or impossible, two records no field tells apart, and an action performed on one branch of a choice that holds nothing deciding it. An answer is a run of the same construction over instances: each pass asks Pydantic for every class of the route not yet in its scope whose premises are present, fans out a child scope per element, performs the actions that constructed together in one task group, and stops when the route itself constructs; a pass that builds nothing names each relation or selection that did not hold, with the ordering observed. The engine keeps nothing about a program between runs: the proof is a value the server computes once and passes to every answer. One span per answer, one per performed action.

`tests/type_construction_engine/` holds the programs the tests are, and the scenarios in `tests/features/`.
